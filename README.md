# 视频压缩 / 截取工具 — 使用说明

一个双击即用的本地小工具：把视频拖进来，就能**压缩体积**或**截取片段**。
**无需安装任何软件**——ffmpeg 编码器与 Python 运行时都已内置在文件夹中。

## 特性

- **零依赖**：内置 ffmpeg 4.2.2 + Python 3.13.7，目标电脑无需安装任何环境
- **两种压缩方式**：按比例（压到原体积的 N%）或按目标大小（指定 MB）
- **体积可控**：两遍编码反推码率，实测误差约 5%
- **片段截取**：`起始秒,结束秒` 精确到帧，附带码率封顶避免体积膨胀
- **输入校验**：非法输入即时提示并允许重填，不会因手误中断流程
- **自动校验**：处理完自动全片解码，确认输出可播放
- **不破坏源文件**：只读源文件，输出另存新文件，同名自动加序号
- **纯本地**：不联网、不上传任何素材

> 技术栈：Python 3（仅标准库）+ ffmpeg（H.264 / AAC）
> 许可证：本项目代码 MIT；内置 ffmpeg 为 GPL，详见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)

## 一、放到桌面

把这个 **`视频压缩工具`** 整个文件夹剪切到桌面即可，例如：

```
C:\Users\你的用户名\Desktop\视频压缩工具\
```

文件夹内部结构（**整个文件夹一起用，不要单独移动某个文件**）：

```
视频压缩工具/
├─ compress-video.bat    ← 把视频拖到它身上（入口）
├─ video-compress.py     ← 主程序，不用直接双击
├─ README.md             ← 本说明
├─ bin/
│  └─ ffmpeg.exe         ← 内置编码器（62MB），删了就不能用
└─ runtime/
   └─ python.exe 等      ← 内置 Python 运行时（21MB），删了就不能用
```

> `bin` 和 `runtime` 两个子文件夹是工具的"发动机"，**必须随文件夹一起复制**。
> 有它们，任何一台 Windows 电脑都不用安装任何软件。

## 二、三步开始用

1. 用鼠标把**视频文件**拖到 `compress-video.bat` 图标上，松手。
2. 黑色的命令行窗口会弹出，先显示这个视频的**原始信息**：

```
[ 原始信息 ]
  文件      黑豹四足机器人.mp4
  位置      E:\...\图件与视频
  分辨率    1920 x 1080
  时长      00:52.4（共 52.4 秒）
  大小      65.6 MB
  帧率      30 fps
  视频码率  10183 kbps
  音轨      有
```

3. 然后按提示选择 **1 压缩** 或 **2 截取片段**，输入参数，回车确认。

处理完成后窗口会显示输出文件的路径、大小、耗时，并自动做一次**全片解码校验**，确认能正常播放。

> 也可以双击 `compress-video.bat`（不拖文件），程序会提示你把视频路径粘贴进去。

## 三、模式一：压缩

选择 `1` 后，会再问一次压缩方式，**两种写法**：

### 写法 A：按比例（压缩到原体积的百分之几）

```
[ 压缩方式 ]
  1) 按比例    —— 输入百分比，如 80 表示压缩到原体积的 80%
  2) 按目标大小 —— 输入数字，单位为 MB（兆字节），如 10 表示 10MB
```

选 `1`，然后输入 **1–99 之间的数字**，**单位是 %（百分比）**，指"压到原体积的百分之多少"：

| 你输入 | 含义 | 以 65.6 MB 原片为例，目标约 |
|---|---|---|
| `80` | 压到原体积的 80% | 52.5 MB |
| `60` | 压到原体积的 60% | 39.4 MB |
| `40` | 压到原体积的 40% | 26.3 MB |
| `20` | 压到原体积的 20% | 13.1 MB |

注意：输入 `40` 不是"压缩掉 40%"，而是"**压缩到 40%**"（即压掉 60%）。

### 写法 B：按目标大小（直接给一个体积）

选 `2`，然后输入**纯数字**，**单位是 MB（兆字节）**：

| 你输入 | 含义 |
|---|---|
| `10` | 目标文件约 10 MB |
| `25` | 目标文件约 25 MB |
| `8.5` | 目标文件约 8.5 MB |

> **单位再确认一次：**
> - 按比例 → 数字是 **%**，取值 1–99
> - 按目标大小 → 数字是 **MB**（兆字节），直接写数字，不用加单位

程序会做两项检查并提示重填：

- 目标不得 ≥ 原文件大小（那样没有压缩意义）
- 目标小于 0.5 MB 会拒绝（体积太小已无法保证可看性）

### 压缩是怎么做到"接近目标体积"的

程序用**两遍编码**：第一遍分析画面复杂度，第二遍按反推的码率精确分配。
计算公式：`视频码率 ≈ (目标MB × 8192 ÷ 时长秒) × 98% − 音频码率`。
实测 10 MB 目标得到 9.4 MB、20% 比例（13.1 MB）得到 12.3 MB，误差约 5% 以内。

分辨率会按最终码率自动下调，避免"码率不够还硬撑高分辨率"导致的糊化：

| 可用视频码率 | 自动输出分辨率 |
|---|---|
| ≥ 2400 kbps | 1080p |
| 950 – 2400 kbps | 720p |
| 520 – 950 kbps | 540p |
| < 520 kbps | 360p |

原始视频比目标分辨率还小时，**不会放大**。

## 四、模式二：截取片段

选择 `2` 后，按下面的格式输入：

```
起始秒,结束秒
```

- 分隔符用**英文逗号 `,`** 或**中文逗号 `，`** 都可以
- 单位是**秒**，可以写小数（如 `12.5,30`）

示例：

| 你输入 | 结果 |
|---|---|
| `30,90` | 从第 30 秒截到第 90 秒，共 60 秒 |
| `0,15` | 截取开头 15 秒 |
| `12.5,30` | 从第 12.5 秒截到第 30 秒 |

校验规则（不合法会提示并让你重填）：

- 必须正好两个数字，否则提示"需用逗号分隔"
- 结束时间必须大于起始时间
- 起始时间不能超过视频总时长
- 结束时间超出总时长时，会提示"已修正"并自动截到片尾
- 区间至少 0.5 秒

截取采用**重编码**而非直接剪切，好处是切点精确到帧，不会出现开头黑屏或音画错位；同时把码率上限设为原片码率，避免重编码后体积反而膨胀。

## 五、输出文件在哪里

**始终输出到源视频所在的同一个文件夹**，文件名自动加后缀，**原始文件绝不修改、绝不覆盖**：

| 操作 | 输出文件名 |
|---|---|
| 压缩 | `原文件名_压缩.mp4` |
| 截取 | `原文件名_截取_30-90s.mp4` |

若同名文件已存在，自动改为 `_压缩(2).mp4`、`_压缩(3).mp4`，不会覆盖旧成品。

输出统一为 **MP4（H.264 + AAC）**，并写入 `faststart`，便于在 PPT 里插入、网页里播放、手机直接看。

## 六、常见问题

**Q1：窗口一闪就没了 / 提示 `video-compress.py is missing`**
说明文件没放全。请确认 `compress-video.bat`、`video-compress.py`、`bin\ffmpeg.exe` 三者在同一套目录结构里，且没有把 `.bat` 单独复制到别处。

**Q2：提示 `bin\ffmpeg.exe is missing`**
内置编码器被删或被杀毒软件隔离了。从原文件夹里把 `bin` 目录整体复制回来；若已被隔离，需在杀毒软件里恢复并加白名单（ffmpeg 常被误报）。

**Q3：提示 `No Python runtime found` / `The bundled runtime folder is missing`**
说明 `runtime` 子文件夹没跟过来（常见于只复制了 `.bat`，或解压不完整）。
请把整个 `视频压缩工具` 文件夹完整复制，确认里面同时有 `bin\ffmpeg.exe` 和 `runtime\python.exe`。
本工具**不需要**你另外安装 Python——运行时已经打包在内。

**Q4：窗口里中文是乱码**
本工具已设置 UTF-8 代码页。若仍乱码，在窗口标题栏右键 →「属性」→「字体」，改为 `Consolas` 或 `新宋体`；或在运行前手动执行 `chcp 65001`。

**Q5：压缩后体积没到目标值 / 比目标略大**
两遍编码是"尽量贴近"而非"精确等于"，正常误差在 5% 左右。若明显偏大，通常是因为：
- 目标体积过小，码率已到 120 kbps 下限（程序会提示"画质会明显下降"）
- 视频极短（如 3 秒），封装开销占比高
此时把目标调大一点即可。

**Q6：压缩后画质下降明显怎么办**
换更大的目标体积。经验值：1080p 素材压到 **原体积 20%–40%** 通常仍可看清细节；压到 10% 以下一般只适合"能看清动作"的场合。

**Q7：能保留 1080p 只减小体积吗**
可以。选「按比例」并输入较大的值（如 60 或 80），码率足够时程序会自动保持 1080p。
如果目标体积很小却仍想要 1080p，画质损失会很明显，不建议。

**Q8：能一次处理多个视频吗**
当前一次处理一个。处理完会问"还要处理其他文件吗？(y/N)"，答 `y` 继续下一个，不必重新拖拽。

**Q9：处理要多久**
约为视频时长的 **0.4–0.8 倍**（两遍编码）。52 秒视频约 20–25 秒；10 分钟视频约 4–8 分钟。压缩比截取慢，因为压缩要跑两遍。

**Q10：原视频会被改动吗**
不会。程序只读取源文件，输出永远是新文件。

**Q11：支持哪些格式**
mp4 / mov / avi / mkv / m4v / wmv / flv / ts / webm / mpg / mpeg / 3gp / rmvb。输出统一为 mp4。
需要说明的是：封装格式很老或编码很特殊的文件，可能无法解析，此时会提示"无法解析该文件"。

**Q12：视频没有音轨能处理吗**
可以，程序会自动检测并跳过音频，不会因为缺音轨而报错。

## 七、分享给别人

**可以，把整个文件夹打包发过去就行，对方电脑不需要安装任何东西。**

### 正确做法

1. 右键 `视频压缩工具` 文件夹 →「压缩为 ZIP 文件」（或"发送到 → 压缩(zipped)文件夹"）
2. 生成的 `视频压缩工具.zip` 约 40–50 MB，通过微信 / QQ / 网盘发送
3. 对方解压后，把视频拖到 `compress-video.bat` 上即可使用

**不要**只发 `.bat` 或只发 `.py`：两者必须和 `bin`、`runtime` 两个子文件夹在一起才能运行。

### 对方电脑的要求

| 项目 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 7 及以上（64 位） | 32 位系统不支持，因为内置的是 64 位编码器 |
| 软件环境 | **无需任何安装** | Python 与 ffmpeg 均已内置 |
| 磁盘空间 | 约 100 MB | 解压后 82 MB，另需容纳输出视频 |
| 网络 | 不需要 | 纯本地运行，不上传任何文件 |

### 三个可能的坑

1. **杀毒软件误报**：ffmpeg 和 python.exe 偶尔会被 Windows Defender 或国产杀软标为可疑，通常是"未签名的可执行文件"导致。让对方选择"允许 / 恢复"并加入白名单即可；发给别人前可以先说明一句，避免对方以为是病毒。
2. **解压不完整**：用微信直接"打开"压缩包而不解压，可能导致 `bin`、`runtime` 缺失。要求对方**先解压再使用**。
3. **路径太长或含特殊符号**：解压到桌面或 D 盘根目录最稳妥，避免嵌套很深的目录。

### 不建议的做法

- 只发 `.bat`：对方双击会报"缺少 video-compress.py"
- 发到 Mac 上用：`.bat` 是 Windows 批处理，macOS 无法直接运行
- 放在 OneDrive 等同步盘的只读目录里运行：可能导致无法写出临时文件

## 八、技术说明（可跳过）

- 编码器：ffmpeg 4.2.2 静态构建（内置，`bin\ffmpeg.exe`）
- 运行时：Python 3.13.7 embeddable（内置，`runtime\`），**无需用户安装 Python**
- 压缩：H.264 两遍编码，`preset slow`，AAC 96 kbps 立体声
- 截取：H.264 CRF 20，`preset medium`，AAC 128 kbps，码率上限 = 源片码率 × 1.05
- 依赖：仅使用 Python 标准库，无需 pip 安装任何包，无需联网
- 输出均带 `+faststart`（moov 前置），便于边下边播
